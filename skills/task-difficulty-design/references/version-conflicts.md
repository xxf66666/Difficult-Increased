# 版本冲突与一致组合

用于题目被“取最高版本、取最新日期、整包换新版”轻易完成的情况。目标不是多放几份旧文件，而是让模型恢复版本身份、继承关系与适用条件，形成可以共同使用的规则、参数和事实，再用于实际业务决定。

[跨文件证据](cross-file-evidence.md) 的 E2/E3/E7 已覆盖时间、来源依赖与变更传播，[规则组合](rule-composition.md) 的 R1/R2 已覆盖局部修订与状态变化。本页深化版本谱系、修订合成、组合兼容与实际落地偏离；同一判断不能因归入多个编号而重复计工作量。按业务需要选用，不要求每题全部具备。

## 先拆开版本的几个维度

| 维度 | 输入中应能恢复的依据 | 不能直接推定的结论 |
|---|---|---|
| 身份与谱系 | 文档/对象标识、分支、共同基线、引用或修订范围 | 版本号更大就覆盖其他分支；同名同号就是同一内容 |
| 时间与效力 | 签发权限、批准/发布/送达/启用时点、生效区间、适用对象及过渡条件 | 已发布就已生效；已批准就已启用；新版自动改写历史事项 |
| 组合与口径 | 配套引用、参数定义、单位、对象粒度、兼容或迁移条件 | 单份分别有效就能共同使用；所有文件必须同一版本号 |
| 实际发生 | 使用、交接、执行、冲回或更正记录 | 应当按新规则执行，就证明实际上已按新规则完成 |

日期真正影响判断时，材料应说明其含义和边界；任务明确决策时点，必要时区分“当时可知”与“现在重述”，具体按 E2。版本身份可以由编号、页内引用、导出来源、修订记录或内容特征恢复，不强制每份材料都提供哈希。不凭文件修改时间、文件名里的“最终版”或作者私下指定来裁定。

## V1 分支谱系与共同基线

**材料改造：**保留同一基线派生的客户版、区域版、产品变体或维护分支，以及其普通修订记录、引用和适用对象。让两个版本分别在自己的范围内有效，版本号不构成全局顺序。关键身份线索分布于业务记录中，不先替模型编好“对象—正确版本”总表。

**判断与后果：**恢复当前对象属于哪个分支、继承哪些基线要求，哪些相似文件仅适用于别的对象。选择会改变资格、参数、计价或可执行范围；并行分支的内容可能相容，也可能不能直接合并，不能因为都来自一个祖先就把改动全部叠上。

**可解检查：**对象与分支有连接依据，实际重叠处有合并、优先或保留未决的依据。材料没有保存完整历史时，只要求能从现有证据恢复的状态，不要求猜出每个中间版本。正常通用对象与分支对象都应存在，防止“全部拒绝”代替判断。

## V2 累积修订、快照与局部覆盖

**材料改造：**让完整快照、增量通知和局部补丁共存，保留快照已包含哪些变更、补丁基于哪一版、替换哪些字段或对象的依据。可设计“醒目汇总已吸收一项调整，另一份通知仍在流转”的情形；它必须嵌在完整业务材料中，不能只做几行的重复调整陷阱。

**判断与后果：**区分整值替换、净增量、已累计变化和范围限定的修订。不能把快照当增量相加，也不能对已包含的变更再应用一次；局部修订以外的有效条件仍可能继承。正确合成后，数量、费用、限额或承诺应实际不同。

**可解检查：**作者复算基线加适用变更是否能得到对应快照；发生重叠时，不能默认为“后收到的赢”。保留合法的重复转发和未受影响对象，验证“全部去重”“全部累加”“整份用新版”都不能替代具体判断。此处接 R1/E3，不另算一轮规则处理。

## V3 单份有效，组合却不兼容

**材料改造：**让规格、参数表、计算口径、检验要求或执行配置各自有版本，配套关系依赖接口、工况、对象批次、字段含义或迁移条件。例如一份新表改变了单位或统计对象，旧计算底稿仍按原含义取值。兼容条件留在正常说明、引用和交接记录中，不提供作者已经拼好的唯一正确组合。

**判断与后果：**模型需要找到能共同使用的一组版本，而不是逐文件各挑最新。旧组件可以有依据地继续配合新组件；编号相同也不能证明兼容。口径映射成立后再计算；映射不能恢复时，将阻断限定到受影响对象，不能猜一个换算系数。

**可解检查：**至少有符合业务目标的可用组合，或任务接受有依据的局部阻断与可完成部分。若要求迁移，必要映射、条件与权限必须可恢复；不能靠缺失接口定义制造难度。组合判断应改变方案可行性或结果，接受高效联合求解和合理替代组合，不强制逐版本试错。

## V4 批准版、分发版、引用版与执行版不同步

**材料改造：**保留正式变更、送达记录、现场启用记录、底层快照以及由它们产生的正常报表。允许新导出的报表仍引用旧底表，或已批准的新规范尚未在部分对象上启用；显示时间与底层事实时间不能被提前清洗成同一个字段。

**判断与后果：**分别恢复“按有效要求应使用什么”和“有证据表明实际使用了什么”。分发滞后、缓存未更新与合法过渡使用需要区分；旧材料也可能在其范围内正确。由此确认哪些结果可用、哪些需要纠正或待核，而不是用新规范重写已经发生的事实，或把已发生自动视为合规。

**可解检查：**批准、送达和实际执行各有对应依据；新旧衔接、存量事项如何处理由业务材料支撑，不默认有或没有过渡期。多份报表转抄同一旧底表只是共同来源，接 E3；实际采用版本不足以确认时，保留具体未决范围，不能让作者的私有日志成为唯一答案。

## V5 回滚、撤销与不可逆结果

**材料改造：**保留撤销或回退的作用范围、仍保留的变更、执行前后对象状态，以及必要的冲回、更正、迁移或补偿记录。可以让文档恢复旧版，但此前已完成的发货、占用、付款或承诺仍有业务后果；不要把回退写成无依据的全量重置。

**判断与后果：**区分取消一项规则、恢复某个参数、撤销未执行安排和处理已发生事项。撤销例外不自动证明所有历史结果都失效，也不自动证明某条旧规则已经恢复。按实际依据更新可用量、责任、安排和承诺，并保持仍有效的变化。

**可解检查：**每个需要恢复的状态都有输入依据，冲回与原事件能连接且不重复计量。涉及不可逆动作时，模型可以给出有边界的纠正方案，不能要求抹掉事实。接 R2 与 [执行联动](coupled-execution.md) 的 L4，结束于共同可执行的结果，不要求固定返工次数。

## 把版本裁定接到难度和必要工作

作者侧记录这条依赖：`版本身份与谱系 → 对象/时点的适用组合 → 状态、参数或口径 → 计算与方案 → 受影响交付与独立核对`。只有确实改变后续结果的连接才保留；列一张版本清单、找几个错字或多读几份相同副本不能证明轮次增加。

为拟采用的机制试做合理便捷路径：最高版本全覆盖、最新导出当最新事实、单文件分别挑新版、所有补丁都叠加、回滚就恢复全部原状。确认所选误判确实影响业务结果，并用输入内的依据恢复；无需设计成每种捷径都错误。模型直接恢复正确组合也应接受。具体成对核验按 [业务逻辑与可恢复陷阱](business-logic-and-recovery.md)，修复范围按 E7/L4，不重复累计工作量。

## 题面、附件与作者记录

题面说明业务委托、对象范围、决策时点及需要的结果，不列正确版本、冲突位置、合并顺序或哪些旧文件可以忽略。中性目录和真实版本标识可以保留；有业务作用的批准、草案、作废和撤销状态也应保留，不用隐藏它们来人为卡住判断。

附件保留完整相关章节、普通修订、例行记录、未受影响对象及充分原生噪声。短通知回到邮件链或变更记录上下文；禁止一版本一条线索的小附件。不要统一重排成一张干净的“各版本差异及正确结论”表。见 [输入附件要求](prompt-and-attachments.md)。

作者整理的谱系结论、正确组合、误判后果和修复清单填写在 [作者记录](../assets/design-record.md)，不进入模型输入；供模型恢复谱系与兼容关系的原始引用、修订和执行依据仍保留在输入中。输入在试测前冻结；单轮任务可一次提供完整历史，不在看到模型答对后偷偷改附件或补隐藏条件。业务确为动态任务时，事先说明变更机制并逐轮留存输入，按 [轮次与验证](rounds-and-validation.md) 计数。
