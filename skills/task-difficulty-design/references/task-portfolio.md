# 同领域多题设计与能力层次

在用户要求同一行业、专业领域或岗位出一组题时使用。先形成有业务依据的候选方向，再制作具体题目；用户要求八道时规划八道，数量随当前委托变化。方向清单属于作者材料，不放入模型题面。

## 五种方向拆分

围绕熟悉的领域，挑能改变实际工作内容的拆分维度组合使用，不必跨行业或硬换岗位：

| 拆分维度 | 找什么变化 | 什么时候只是换皮 |
|---|---|---|
| 业务场景 | 正常运营、突发变化、新产品导入等不同条件下，决定什么、为什么现在必须决定 | 只换背景名称，输入关系与判断路线仍相同 |
| 工作任务 | 核算、诊断、审核、排程、方案取舍等不同的业务结果 | 同一分析分别导出报告、表格和演示文稿 |
| 分析视角 | 同一问题中不同的证据、约束和可验证结论，如容量、质量、成本 | 同一汇总表换几种图，或同一报告换标题 |
| 客户或服务对象 | 不同对象的需求、可接受条件、权限和使用方式 | 只换接收人的称呼，没有约束变化 |
| 精准判断 | 可复算的数值、资格、范围、阈值、有效状态或对账结论 | 一个公式换一批数字，或把同一判断拆成多道小题 |

每个候选写清：业务委托、要作出的决定、所需资料及当前缺口、关键约束、必要交付、主要难点、下游工作。资料按业务来源组织，允许共享基础制度或同一原始记录，不要求为了“不同材料”复制改名或另造一套无用文件。

## 按核心判断去重

给各题建立作者内部对照：

| 方向 | 场景/对象 | 核心决定 | 证据与口径 | 约束组合 | 交付结果与必要工作 | 与其他题的实质差异 |
|---|---|---|---|---|---|---|
| 按本次领域填写 | | | | | | |

两两检查：如果某题的已有解法只需改名称、替换数字、换接收人或导出格式，就能完成另一题，两者高度同质，应合并或修改核心任务。真正的差异要落在证据裁定、可行域、取舍目标或必须交付的结果上，不能只数维度变化。

相同资料可以支持不同任务，但应有不同的决定和工作依赖。也检查答案串用：一题的产物是否已经替另一题完成全部难点？若形成连续任务，应明确承接关系，不把同一判断重复计为两个独立难题。

下面仅演示离散制造领域的方向差异，不是八道已完成、已验证的题目；不把表格拆成几行一份的输入附件：

| 方向 | 主要证据 | 核心判断与后续工作 |
|---|---|---|
| 插单后的交付安排 | 订单变更、在制品、台位与班次记录 | 还原截止时点容量与占用，协调订单竞争并更新承诺 |
| 新产品工艺转移 | 试制、参数、能力与验收记录 | 裁定可用证据与适用窗口，形成分阶段放行安排 |
| 异常批次处置 | 量测、追溯、返工及质量规则 | 还原影响对象，区分隔离、返工和可放行范围 |
| 替代料切换 | 规格、库存、验证及批准记录 | 判断替代适用范围，落实用量、切换时点与风险条件 |
| 月度成本与结算核对 | 产量、耗用、报废、费用及结算明细 | 恢复数量和计价口径，解释差异并复算结果 |
| 大修窗口安排 | 故障、维护、备件与生产计划 | 权衡停机风险和共享资源，求解可执行窗口 |
| 特定客户的交付资格 | 客户约定、版本、批次及检验记录 | 逐批裁定资格，形成可交付范围与缺口安排 |
| 退货责任与维修安排 | 服务约定、故障、变更及维修记录 | 判断责任和有效服务范围，再安排费用、物料与交期 |

实际选题时用本次业务材料核验这些差异；不以表中方向名称保证难度。

## H1–H6 能力层次：查缺口，不强制六段流水线

源文使用 L1–L6；此处采用 H1–H6，避免与 [执行联动](coupled-execution.md) 的 L1–L8 方法编号混淆。层次用于定位题目与考点的覆盖，编号不代表实测难度，也不要求每题全部具备。

| 层次 | 模型必须完成的能力 | 能接到什么必要工作 |
|---|---|---|
| H1 信息加工 | 提取、识别口径、恢复对象与字段 | 形成可用输入，保留需核对的差异 |
| H2 逐对象处理 | 按不同条件应用规则，覆盖应处理对象 | 逐项结果、可回到明细的汇总 |
| H3 辨别与仲裁 | 裁定权限、时点、范围、冲突和可恢复错误 | 改变有效数据、对象状态或规则适用 |
| H4 约束求解 | 处理容量、资格、时序与资源竞争 | 构成共同可执行的方案，而非各对象独立正确 |
| H5 动态重算 | 识别变更影响范围，重算受影响部分 | 同步承诺与产物，保持未受影响部分 |
| H6 业务取舍 | 依据目标和证据选择立场、范围与可接受代价 | 可解释的决策及执行边界，接受满足约束的替代解 |

H1、H2 可以很难，H6 也可能只剩空泛意见；关键看输入依赖、判断成本和后果。需要深化时，将一个恢复或裁定结果传到约束、方案、情景和复核，而非在题面列出六个强制操作阶段。

## 每道单独落实与核验

优先从材料最充分、业务最熟悉的方向验证方法，再逐题落地，不把后续题简化成凑数版本：

- 把委托写进 prompt，把原始背景、错误噪声与跨源依据放在附件；确保筛选和关联没有提前完成。
- 对照 [执行联动](coupled-execution.md)，确认上游判断改变后续工作；允许批处理、合并读取、合理求解和并行，不要求操作阶段不可合并。
- 检查附件贡献：移走某份材料，会损失什么范围、裁定依据、纠错或核验能力？必要的原生上下文和冗余仍可保留，不要求抽掉任意文件就必须整题无解。
- 用 [考点写法](rubric-writing.md) 检查各题是否覆盖主要专业判断；题目、输入、作者答案、考点和作者思路应相互一致，并按本次交付范围提供。
- 分别记录各题的可解性、已验证内容、得分和必要执行。共享方法、格式或基础材料不能代替每道题的验证；一题通过不能推断其余通过。

数量、阶段数、附件数和能力编号都不能证明难度。指定的得分、轮次或时长条件按 [当前计数口径](rounds-and-validation.md) 逐题核对，不将源文项目门槛设为跨项目默认值。
