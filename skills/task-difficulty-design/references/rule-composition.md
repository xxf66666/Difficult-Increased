# 跨规则组合：让同一判断改变后续工作

本页是基于现有方法新增的作者设计建议，包含抽象推导和教学小例子，不是来源文件的逐条摘录，也不代表已经实测提升难度或轮次。小例子只说明逻辑，不声称来自任何行业的实际条款。

可以主动增加规则之间的依赖，让单条规则容易理解、组合应用需要判断。关键是这些组合服务于同一任务目标，能从模型可见材料恢复，且确实改变计算、选择、执行或验证。

以下“附件布局”指组织任务材料的方法；“prompt 边界”指题面应说明的委托。方法编号、作者组合表、正确应用次序和故障定位均留在作者材料中，不直接改写成模型的解题清单。

## R1 适用域交叉与部分覆盖

**如何设计：**让多条规则在对象、区域、时间、状态和字段上存在交集。新条款只替换特定范围内的某一要求，其余要求继续继承；对象资格变化也可能使例外不再适用。

**附件布局 / prompt 边界：**基础规则、局部修订、对象属性和时点记录按各自业务来源保留。材料须能恢复修订的覆盖范围；题面要求给出当前可用结果及必要依据，不直接告诉模型“先找补丁再继承旧规则”。

**判断难点：**“新文件覆盖旧文件”不足以求解。模型要区分替换、补充、豁免和适用域外，并避免把某字段的豁免扩大为整个对象的豁免。

**必要执行及下游影响：**将对象与适用域关联，合成各对象实际约束，再据此计算数量、成本或可执行范围；范围变化后，相关明细和汇总都需要更新。

**可解检查：**为实际出现的交集给出唯一可解释的覆盖关系，或明确允许保留未决状态。保留域内、域外和部分命中对象，检查一律用新规则、一律用旧规则都不能正确完成。

## R2 事件触发后的状态迁移

**如何设计：**让某条规则改变对象状态，后续规则读取改变后的状态。例如资源被占用后不能再次分配，满足释放条件后才能恢复；撤销发生时还需区分未执行与已执行部分。

**附件布局 / prompt 边界：**对象初始状态、事件记录、触发条件和回退条件分别保留。题面明确决策截止时点与需要交付的状态/安排，不提示哪个事件会触发哪条例外。

**判断难点：**规则输入不是一组静态标签。模型必须分清事件发生时间、记录时间和生效时间，判断一次触发是否已经消费额度、改变资格或形成不可自动撤回的结果。

**必要执行及下游影响：**恢复状态轨迹，确定当前可用资源，再生成执行安排；某事件失效时，重新计算受影响后续，而不是只改摘要中的一句状态描述。

**可解检查：**每个必需状态转移都有触发依据；重复事件有识别依据；同一时刻的冲突有顺序或并行语义。若缺少排序依据，应接受等价结果或局部未决，不能暗设作者偏好的顺序。

## R3 运算顺序不交换

**如何设计：**选择先后顺序会改变结果的实际操作，如折算与封顶、扣减与比例计算、分组与去重、资源预留与分配。顺序应由材料中的业务定义决定。

**附件布局 / prompt 边界：**提供操作依据、计量基础和适用时点，保留不同系统的中间值或摘要以供核对。题面要求最终可用结果，不直接给出运算链或逐步公式。

**判断难点：**各条规则都理解正确，仍可能由于组合次序错误而得出看似合理的答案；一个恰好相等的普通样本还可能掩盖错误。

**必要执行及下游影响：**明确每步消费什么输入，执行正确的组合，并用顺序敏感对象校验；错误顺序可能改变总额、资格或最终选择，需要向下游传递修订。

**可解检查：**必要次序能从材料恢复；至少存在一个顺序确实影响结果的对象。相互可交换的操作允许合并或并行，不要求机械分步调用。

**教学小例子：**初值为 100，操作 D 为减 20，操作 S 为乘 0.8。若材料规定 D 后 S，结果是 `(100 − 20) × 0.8 = 64`；反序结果为 `100 × 0.8 − 20 = 60`。例子仅证明顺序有影响，不能直接当作真实任务难度已成立的证据。

## R4 共享预算或容量的跨对象竞争

**如何设计：**让多个各自合格的对象争用同一资源，且资源可能同时有金额、时间窗、位置或技能等维度。接受一个对象会改变其他对象的可行性。

**附件布局 / prompt 边界：**对象需求、资源台账、已有占用和选择目标分别来自相应材料。题面明确要交付一套可共同执行的方案，必要时给出优化目标；不把对象预先排好序。

**判断难点：**逐对象通过检查不能推出整体可执行。按单一收益、最低成本或先来后到贪心，可能错失更好的组合，也可能重复使用已经占用的容量。

**必要执行及下游影响：**联合选择、分配并验证资源余额；容量或对象资格变化后，重算受影响组合，更新被选对象、未选原因和最终承诺。

**可解检查：**需求与容量的单位、期间、可分割性清楚；目标与允许的替代解明确。作者独立找到至少一个可行方案，并核验声称的最优性，不能把“看起来不错”当唯一标答。

**教学小例子：**两种资源容量各为 4；对象不可拆分，收益可相加。

| 对象 | 资源甲需求 | 资源乙需求 | 收益 |
|---|---:|---:|---:|
| A | 3 | 1 | 8 |
| B | 1 | 3 | 8 |
| C | 2 | 2 | 7 |

三个对象单独都可行。A+B 消耗 `(4,4)`、收益 16；A+C 为 `(5,3)`、B+C 为 `(3,5)`，都不可行；全选为 `(6,6)`。因此最优组合为 A+B。这个小例子检验联合约束，放大对象数本身不保证有效轮次增加。

## R5 边界精度、分段阈值与计量口径

**如何设计：**让规则依赖明确的开闭区间、分段计量、单位换算或舍入时点。组合难点可以来自“按对象计算再汇总”与“先汇总再计算”具有不同语义。

**附件布局 / prompt 边界：**原始精度、计量单位、区间定义和计价/计量规则分布在数据说明与业务材料中。题面写明交付精度等必要要求，不标出临界记录，也不预告哪个字段需要特殊处理。

**判断难点：**展示值不能直接替代计算值；“超过”不同于“达到”；分段累进不同于全量改用新系数。局部数值很小的差别可能改变资格和方案选择。

**必要执行及下游影响：**恢复口径、正确计算各段、核验边界和汇总；再以结果作后续决策。统一精度应在正确环节发生，不能用舍入掩盖超限。

**可解检查：**所有会影响答案的边界与舍入规则都有依据。若来源确实允许多种精度解释，应给合理容差或接受条件性答案，不把浮点实现细节变成隐藏考点。

**教学小例子：**非负数量 q 的费用定义为：前 10 单位每单位 2，超过部分每单位 3；最终费用以十进制四舍五入保留两位，中间不舍入。q=10.005 时，费用为 `20 + 0.005 × 3 = 20.015`，最终是 20.02；先把 q 舍入为 10.01 再计算会错成 20.03。

## R6 局部通过与全局可行性分离

**如何设计：**使各局部条件分别成立，但整体还需满足跨阶段关系，如前置依赖、交接时间、流量守恒、全程连续性或闭环平衡。该方法与 R4 的区别是，即使总资源充足，组合仍可能无法执行。

**附件布局 / prompt 边界：**各阶段能力、连接关系、转换损耗和时窗保留在对应材料中。题面要求完整可执行成果及必要验证，不指出哪一对阶段存在冲突。

**判断难点：**把若干局部“通过”相加不能证明整条链成立。模型需检查对象能否从起点连续到达终点，阶段输出是否满足下游输入，以及总量与逐时状态是否一致。

**必要执行及下游影响：**建立阶段连接，求出整体方案并回代；若局部方案冲突，调整相关阶段，再同步总计划、阶段清单与交付承诺。

**可解检查：**连接关系与损耗有输入依据；至少有可行完整路径，或任务明确接受有证据的局部阻断成果。作者应实际回代全链，不能只分别检查各阶段。

## R7 最小修改修复与改动传播

**如何设计：**在一个既有方案上给出会改变可行性的实际条件，要求修复方案，同时控制重做成本。保留哪些内容、允许改变哪些内容，以及“更小改动”如何比较，都须有任务依据。

**附件布局 / prompt 边界：**保留基线方案、变化材料、不可变承诺和修改成本。题面可以要求在满足新条件的前提下减少改动，但不要直接提供故障位置、最小修改集或传播路径。

**判断难点：**发现错误只是开始；局部补丁可能造成新的约束冲突，全面重做又可能违反已有承诺。模型还要判断哪些旧结果仍然有效、哪些必须重算。

**必要执行及下游影响：**定位受影响范围，比较候选修复，更新依赖成果，再验证修复后整体可行及未受影响承诺；只改报告措辞不能完成。

**可解检查：**基线、变化和允许改动范围完整；“最小”有可计算口径，如变更对象数优先、再比较变更成本。若只要求合理少改，就不能用隐藏的全局最优标准判错。

## R8 多目标权衡与可接受多解

**如何设计：**让两个有实际意义的目标存在冲突，例如成本与周期；先满足硬约束，再辨别被支配方案与合理取舍。目标之间没有业务依据时，不私设权重强行合成一个总分。

**附件布局 / prompt 边界：**目标依据、方案数据和硬约束可分布在委托材料、明细和限制说明中。题面可要求比较可行选择并提出建议；若必须唯一选择，须提供足够的优先级或取舍边界。

**判断难点：**便宜不必然最好，最快也不必然可接受。模型要区分不可行、可行但被支配、互不支配与等效方案，不能把多解误判成材料缺失。

**必要执行及下游影响：**筛选可行域、检查支配关系、解释取舍，并把选定方案落实到必要明细。目标或硬约束变化时重新选择，并更新对应安排。

**可解检查：**不要求枚举对业务无用的巨大前沿。若存在多个合理解，作者记录接受条件；评价约束、证据与实施一致性，不按是否选中作者偏好的名称判分。

**教学小例子：**成本和耗时都越小越好，候选为 A=(8,5)、B=(10,3)、C=(9,6)、D=(8,5)。A 严格支配 C；A 与 B 互不支配；A 与 D 等效。没有额外偏好时，A、B、D 都可作为合理取舍的起点，不能暗定 A 为唯一正确答案。

## 组合选择：只叠加会相互改变结果的方法

| 组合 | 增加的判断 | 必要执行为何增加 |
|---|---|---|
| R1 + R2 | 同一修订在对象不同状态下适用范围不同 | 恢复时点状态后才能确定规则，进而更新执行范围 |
| R3 + R5 | 正确规则还需正确基数、次序与精度 | 对边界对象重新计算并核对下游资格或金额 |
| R4 + R6 | 资源足够仍需阶段衔接成立 | 联合分配后还要回代全链，冲突会导致方案修订 |
| R2 + R7 | 状态变化只使部分旧成果失效 | 识别受影响依赖并修复，验证既有承诺仍成立 |
| R4 + R8 | 多个可行组合存在目标冲突 | 联合选取、比较有效取舍，再落实一套一致安排 |

不要把八种机制强行放进每道题。选择少量能够作用于同一决策的组合，分别核对：去掉该组合后答案或必要工作是否改变；便捷基线是否仍能全部做对；作者是否能独立完成；模型输入是否包含所有必要依据。

## 把预期提升与实际轮次分开

以上机制可以增加状态恢复、规则合成、联合选择、回代和修复等必要工作，但不对应固定消息数或工具调用数。允许模型用脚本、求解器、批处理和并行一次完成多项检查；正常效率不应被限制。

作者记录每次改造新增的判断、消费的上游结果、改变的下游产物及可核验结果。若一条通用规则即可一次处理全部对象，应据实降低轮次预期；继续增加同质对象只能增加数据量。

只有固定输入下的独立作答轨迹和实际产物，才能说明这些改造对指定模型是否有效。未试测时标为“新增设计建议 / 未测”，不把复杂的作者解释当作难度提升或轮次达标的证据。
