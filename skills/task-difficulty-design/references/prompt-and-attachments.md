# 提示词和输入附件

## 提示词的保留与移出

| 保留在模型输入中的信息 | 从题面移到作者材料的内容 |
|---|---|
| 真实委托、用途、截止时点与交付边界 | 先看哪份文件、按何顺序计算 |
| 有业务意义的文件格式、字段、单位、容差 | 解题公式推导、推荐算法、预期中间结论 |
| 必要权限范围与业务约束，或其可检索依据 | 哪一行重复、哪个汇总错误、哪个版本正确 |
| 模型需要知道的专业背景和非通用参数 | 易错点清单、评分点、难点位置和标准答案 |
| 中性的文件名目录（确有需要时） | 逐附件说明“此文件用来解决哪一考点” |

“隐去引导”不等于删掉完成任务必需的事实；“交付明确”也不等于列出固定分析路径。只锁定真实使用需要的格式和精度，不把无业务意义的命名或排版当主要考点。

机制示意：

- 泄露路径的写法：“先排除附件 B 中的撤销记录，再按 C 的例外算金额，最后挑出延期供应商。”
- 更合适的委托结构：“根据随附业务资料，给出截至指定时点可执行的安排，并交付决策说明与执行明细。”

第二种写法仍需补足本项目实际交付内容与边界，不能原样当成万能题面。

## 硬要求：业务材料不夹带作者制作说明

模型可见的题面与附件直接采用业务文档的名称、结构和表达。**不要自行添加“本材料不是真实材料”“构造数据”“模拟数据”“脱敏数据”“仅供出题/测评”“为增加难度生成”等说明，也不要换一种说法表达同样的出题制作信息。** 不需要给每份材料加一段真实性声明。

这项要求覆盖输入包中的文件名、目录说明、封面、正文、页眉页脚、水印、表格备注、批注、隐藏工作表、PDF 元数据及压缩包附带说明。不能只删正文，又把同一说明放进水印、文件属性或 README。

| 内容 | 放置方式 |
|---|---|
| Agent 添加的“脱敏数据.xlsx”“模拟业务记录”“本附件为测评构造” | 去掉作者制作标签，按实际业务内容命名和呈现；需保留的制作记录移到作者侧 |
| “作者发布前删除此行”“当前是待补原件的底稿” | 放在作者修订记录，不能留在可复制题面或交付附件中 |
| 为提升难度做了哪些改动、来源核验结果、加工记录、缺哪些原件 | 仅写入作者记录，不随模型输入包交付 |
| 原资料中的版本、签发/生效日期、来源系统、记录人、对象与批次 | 保留；这些信息支撑跨文件连接和证据裁定 |
| 业务上的草案、待审批、撤销、待核查或未完成状态 | 保留；这些状态可能改变规则效力与下游安排 |

对现有题包，检查并移出先前由 Agent 混入的出题说明；按上下文区分作者标签与业务内容，不做不分语义的关键词批量删除。例如“模拟数据仅供测评”是作者说明，“仿真结果”可能是任务必须分析的工程记录。这里规定的是模型输入的呈现方式，不扩展为材料处理流程或工具使用限制。

发布前按模型实际能读取的范围回读输入包：可见页面与提取文本都查，表格的隐藏内容和文件属性也查。检查记录留在作者侧；不新建“已移除出题说明”的附件。保留事实、业务噪声和连接依据，让难度来自筛选与判断，避免作者说明暴露材料的出题用途。

## 原始材料与噪声

默认先盘点已有资料。在作者台账中记录来源、原始/摘录/导出属性、采集时间及与其他附件的连接关系；未看到的原件也在该台账中记为待补，不把这些制作记录附加到模型输入。

优先保留以下与当前任务有关的原生特征：

- 历史版本、撤销项、正常的空值与系统重复导出。
- 交接记录中的未决事项、观点分歧、无关但自然的上下文。
- 跨系统名称差异、编码、时间粒度和统计口径差异。
- 原文附注、边栏、批注或日志片段中的有效线索。
- 信息充分但结论失效的摘要、仍待审批的候选方案。

用户希望输入附件有较多噪声：扩大业务上下文，避免把输入加工成已清洗的标准答案。也可以主动加入错别字、错数值、错单位、漏项、重复和错汇总，扩充 CSV、表格及其他材料；详见 [原生错误与可恢复噪声](recoverable-noise.md)。需要成立的是底层对象、事件、数量关系和恢复依据，不是要求每条来源记录已经正确、一致。所有依据都被改坏、只能猜数的错误不满足可解性。

视觉噪声仅用于符合场景的附件呈现，不能代替业务噪声，也不能承担“让 OCR 失败”的目标。专业图表、脚注和手写批注如为原件内容可保留；新添的批注不得伪装成历史证据。PDF 处理见 [pdf-authoring.md](pdf-authoring.md)。

## 硬要求：禁止几行一份、只服务一个考点的附件

**模型输入附件不能只由几行文字、几行数据、一条例外或一个结论组成。** 不能把一个考点拆成几个极小文件，再用“跨文件证据”解释这种设计。文件看似多了，关键内容却几乎全部直接有用，模型无需筛选便能拼出作者安排的解题路径。

短小到只剩考点的附件属于需要返工的设计问题，不能以“内容都有用”“已经跨了三个文件”或“文件是真实格式”作为通过理由。几页 PDF 如果实质仍只有几句话，也属于同一问题。

| 不接受的形态 | 为什么容易暴露答案 | 应怎样改 |
|---|---|---|
| 只有三条库存记录，恰好分别对应正常、冲回、重复 | 作者已经挑出了全部关键对象 | 提供相应业务范围的流水、期初依据、普通交易和相关变更上下文，让关键对象需要被识别 |
| 一份文件只写“某条规则暂不适用”，另一份只写“恢复适用” | 两个文件几乎把状态判断过程摆出来了 | 放回完整相关条款、修订范围、往来记录和对象信息，保留其他常规事项及未变化部分 |
| 一封两句话的孤立邮件，刚好给出最后一个参数 | 每份材料都像按解题需要专门写的提示 | 保留对应邮件链、前后回应、引用对象和同一事项的业务上下文，让参数与其他信息一起出现 |
| 每份附件只对应一个对象、一次异常或一个评分点 | 文件划分本身充当答案索引 | 按业务来源、记录周期或文档用途组织，在同一来源中混合正常项、历史项与需判断项 |
| 把很小的表转成多页 PDF，加入水印与装饰 | 视觉体量增加，信息筛选工作没有增加 | 先补足业务材料与信息层次，再制作可读 PDF；不能用排版代替内容 |
| 只给几行挑好的记录，再复制或加随机闲话扩容 | 无需理解就能批量跳过新增内容 | 补入同一工作范围内有上下文关系的普通对象、相似记录和背景内容，让区分依赖事实 |

### 噪声必须足以形成筛选工作

原始材料中大量内容本来不会直接决定最终答案，但仍自然存在。应保留这种状态，而不是先替模型提炼成“最少必需事实集”。可从以下方面补足：

- **范围内的普通记录。** 提供完整业务范围内的对象，关键对象与普通对象共存，避免附件只剩异常样本。
- **相关历史和状态。** 保留前期记录、修订、已结束事项和未变化部分，判断它们是否仍适用需要查看对象、时间与状态。
- **相似而不等同的信息。** 同系列对象、邻近期间、不同库位或不同版本都可能看起来相关，但是否适用必须有可核对的区分依据。
- **工作过程与上下文。** 保留一段事项的来由、讨论、反馈、未采用的备选及后续处理；关键句不单独摘成一张纸。
- **例行字段与非关键内容。** 原始导出中的常规字段、正常空值、备注、文档中的普通条款与非关键段落不因暂不计分就全部删去。
- **分散的连接线索。** 对象对应、时间语义、版本引用可在不同自然位置出现，避免新增一张作者整理的万能映射表把筛选再次做完。

噪声不要统一放在文末“背景资料”区或标成“无关信息”，也不要在文件名、颜色或表格列中预先标出关键项。它应自然混在同一业务来源与记录结构里。与当前任务无关的百科段落、随机乱码或机械重复，不提供这种筛选难度。

### 从薄附件改成可用材料

1. 指出附件目前是否只承载一条答案线索，以及作者已经替模型省掉了哪些阅读、筛选与判断。
2. 恢复其所属的业务范围和前后上下文：同一周期的记录、同一事项的邮件链、完整相关章节或对象沿革。按自然来源重新组织，不按考点拆文件。
3. 保留足够的普通项、历史项和非关键内容，再确认有效证据仍能被找出，底层连接、数量关系与输入中的恢复依据成立；不要求表面记录已经互相一致。
4. 短消息、短规则本身无需改长；把它保留在完整相关资料中，可以按业务关系编写和扩充上下文，不能用无业务关系的填话或机械复制补体量。只把若干考点短句拼成一个大文件，同样没有修复。
5. 区分可以按已知业务关系编写、扩充的内容，与确实未知、不能自行确定的关键事实。后者在作者记录中列明具体缺口与未完成状态，不把缺件说明写入业务附件。不能把几行缩略示意作为正式附件交付，也不能声称噪声已经充分。

### 逐附件与整包检查

作者记录每份附件的以下信息，而非只数页数、行数或文件大小：

| 检查 | 可接受的证据 |
|---|---|
| 除了答案线索，材料还包含什么 | 能具体定位普通记录、背景段落、历史项及其业务来由 |
| 模型必须筛掉或区分哪些内容 | 说明对象、期间、状态、口径或来源上的不同，以及区分依据 |
| 文件是否自然形成 | 组织方式符合来源、事项或业务周期，不是一份文件配一个考点 |
| 打开后能否立即看出全部考点 | 若几句话或几行记录直接列出了需采用的规则与关键参数，应返工 |
| 扩容是否增加实质判断 | 新增内容要求有意义的筛选或关联，不能通过删除统一填充段恢复成同一张简表 |
| 整包是否仍是薄附件的拼盘 | 每份单独合理后，再检查整包是否系统地只保留异常和答案线索 |
| 正确结果是否仍可恢复 | 关键事实清晰可读，必要依据齐全；噪声没有变成无法裁定的矛盾 |

识别出“几行一份”的考点附件、只有答案线索的汇编，或只有装饰性噪声的材料后，先返工这些输入，再扩展其他难度机制。没有完成这项检查，不把材料标成“附件设计完成”。

### 教学小例不能变成正式附件

本技能里的几行数值、短规则和小表格，是为了快速解释运算关系或推理机制，**不是模型输入附件模板**。使用 E、R、L 等方法时，要把机制放进有足够业务上下文与噪声的资料里；不能照抄示意表、套个公司名、导出 PDF，就当作一套题目的输入材料。

## 可解性核验

对每个关键结论建立作者内部证据链：

`输入位置 → 对象连接 → 权限/口径/状态 → 判断 → 结果或待核查边界`

逐项检查：

1. 依据存在于模型可读输入中，或确实允许且可公开检索；不依赖私有账号或未提供的环境。
2. 改造后实体连接、金额关系、相对时间、规则生效区间和状态转换仍可恢复；记录中的错误值不必互相一致，但纠正或保留待核查必须有输入依据。
3. 矛盾可裁定，或明确支持局部待核查；不能悄悄用标答补齐。
4. 正确与错误判断会影响任务结果；检查纠错是否进入后续计算和安排，也检查合法异常是否被误修。无关错字可以存在，不虚报为主要难点。
5. 文件名、目录、隐藏工作表、批注、公式缓存、修订痕迹、PDF 附件/元数据等没有意外暴露作者答案。保留真实业务所需内容，不为消除泄漏而破坏原件；必要时另做有记录的输入副本。

中性材料清单与作者证据索引分开。模型可看到原始资料，不能看到作者整理的“有效规则一览”“冲突裁定总表”或试测评分，除非这些本来就是该真实岗位已知的业务输入；若已知，就不能再把恢复它们计成难点。

## 公开检索

只有项目允许联网，且所需事实可在普通公开渠道取得时才采用。作者记录查询线索、来源、访问日期、版本和所支持的事实，验证不登录也能访问。若动态页面会改变答案，在项目允许时冻结带日期的快照，或明确作答时点。

不以搜索次数为交付要求。若公开资料直接包含整题答案，应检查题目是否只剩检索复述；不能用故意隐去常见关键词来人为卡住搜索。
