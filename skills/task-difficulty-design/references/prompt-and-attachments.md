# 提示词和输入附件

## 提示词的保留与移出

| 保留在模型输入中的信息 | 从题面移到作者材料的内容 |
|---|---|
| 真实委托、用途、截止时点与交付边界 | 先看哪份文件、按何顺序计算 |
| 有业务意义的文件格式、字段、单位、容差 | 解题公式推导、推荐算法、预期中间结论 |
| 必要权限范围与业务约束，或其可检索依据 | 哪一行重复、哪个汇总错误、哪个版本正确 |
| 模型需要知道的专业背景和非通用参数 | 易错点清单、评分点、难点位置和标准答案 |
| 中性的文件名目录（确有需要时） | 逐附件说明“此文件用来解决哪一考点” |

“隐去引导”不等于删掉完成任务必需的事实；“交付明确”也不等于列出固定分析路径。只锁定真实使用需要的格式和精度，不把无业务意义的命名或排版当主要考点。

机制示意：

- 泄露路径的写法：“先排除附件 B 中的撤销记录，再按 C 的例外算金额，最后挑出延期供应商。”
- 更合适的委托结构：“根据随附业务资料，给出截至指定时点可执行的安排，并交付决策说明与执行明细。”

第二种写法仍需补足本项目实际交付内容与边界，不能原样当成万能题面。

## 原始材料与噪声

默认先盘点已有资料。记录来源、原始/摘录/导出属性、采集时间及与其他附件的连接关系。没有看到的原件明确标为待补材料。

优先保留以下与当前任务有关的原生特征：

- 历史版本、撤销项、正常的空值与系统重复导出。
- 交接记录中的未决事项、观点分歧、无关但自然的上下文。
- 跨系统名称差异、编码、时间粒度和统计口径差异。
- 原文附注、边栏、批注或日志片段中的有效线索。
- 信息充分但结论失效的摘要、仍待审批的候选方案。

用户希望输入附件有较多噪声：扩大与真实工作相关的原始上下文，避免把输入加工成已清洗的标准答案。增加背景、旧记录或冗余信息时，应保持同一主体、时间和数量关系成立，不以随机插错替代业务复杂性。

视觉噪声仅用于符合场景的附件呈现，不能代替业务噪声，也不能承担“让 OCR 失败”的目标。专业图表、脚注和手写批注如为原件内容可保留；新添的批注不得伪装成历史证据。PDF 处理见 [pdf-authoring.md](pdf-authoring.md)。

## 可解性核验

对每个关键结论建立作者内部证据链：

`输入位置 → 对象连接 → 权限/口径/状态 → 判断 → 结果或待核查边界`

逐项检查：

1. 依据存在于模型可读输入中，或确实允许且可公开检索；不依赖私有账号或未提供的环境。
2. 改造后实体连接、金额关系、相对时间、规则生效区间和状态转换仍然成立。
3. 矛盾可裁定，或明确支持局部待核查；不能悄悄用标答补齐。
4. 正确与错误判断会影响任务结果；不是故意挑无关边角。
5. 文件名、目录、隐藏工作表、批注、公式缓存、修订痕迹、PDF 附件/元数据等没有意外暴露作者答案。保留真实业务所需内容，不为消除泄漏而破坏原件；必要时另做有记录的输入副本。

中性材料清单与作者证据索引分开。模型可看到原始资料，不能看到作者整理的“有效规则一览”“冲突裁定总表”或试测评分，除非这些本来就是该真实岗位已知的业务输入；若已知，就不能再把恢复它们计成难点。

## 公开检索

只有项目允许联网，且所需事实可在普通公开渠道取得时才采用。作者记录查询线索、来源、访问日期、版本和所支持的事实，验证不登录也能访问。若动态页面会改变答案，在项目允许时冻结带日期的快照，或明确作答时点。

不以搜索次数为交付要求。若公开资料直接包含整题答案，应检查题目是否只剩检索复述；不能用故意隐去常见关键词来人为卡住搜索。
