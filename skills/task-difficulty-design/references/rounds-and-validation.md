# 有效轮次、评分与试测

## 先把指标分开

| 指标 | 必须说明的口径 | 不能拿来替代它的量 |
|---|---|---|
| 难度 | 指定模型、版本、模式、逐考点得分、阈值比较符 | 文件多、时间长、作者觉得难 |
| 多跳结构 | 必要关系、串联依赖深度、分支及汇合条件，记录可绕过或合并的部分 | 所有箭头总数、文件数、实际回复数 |
| 用户交互轮数 | 单轮或多轮委托、后续输入的业务承接 | assistant 消息数 |
| 主模型回复数 | 一条完整 assistant message 的边界 | 消息内 tool calls 数 |
| 有效执行轮次 | 项目认可的事件、排除项、子代理计数政策 | 原始消息、工具返回、脚本循环数 |
| 运行时间 | 起止事件、墙钟或活跃时间、等待扣除规则 | 文件时间戳差、刻意 sleep |

工具调用可以作为辅助统计，但不能默认叫作有效轮次。没有日志格式和项目定义时，保留原始日志并报告口径未明确；不要给一个“通用计数脚本”假装适配所有平台。

按用户当前使用的指标记录实际结果，不预设统一阈值。方法是否有效，要看判断难点与必要工作有没有实质增加。

有验收门槛时保留比较符及 AND/OR 关系，分别报告难度与执行条件。若当前要求允许“轮次或时长满足任一”，其中一项满足即可通过该执行条件；两项同时不足才判执行条件未满足，不能擅自改成两项都必须达标。

## 多跳强度与轮次

用户强调多跳，并认为“20轮内的多跳比较简单”。对本用户的高难度出题设计，将其作为继续加深的偏好：目标模型若按本次约定的有效轮次口径在20轮以内顺利完成关键目标，复核是否需要更深的必要关联、竞争链判别、分支汇合或纠偏后的重算；不能仅凭“已有三跳”就交付为高难度成果。超过20轮也不自动证明达标，仍检查实际结果、错误和有效工作。这是用户设定的强度信号，不是跨模型的普遍实验结论。

在作者侧记录三类量：关系跳数及其计数单位、因果依赖深度与可并行分支、实测有效轮次及计数规则。长链深度不能把互相独立的短链相加；同一对象换名、重复检索、同一事实多种格式不算新增必要关联。轮次口径未确定时先记“未定”，不能把20轮偷偷换成20个文件、20跳、20条考点或20次工具调用。

按 [多跳组合](cross-file-evidence.md#多跳组合与整条关系核验) 增加真正改变后续对象、规则、参数与交付的依赖，再用 [完整路线验证](feasibility-and-shortcuts.md) 和独立作答检查。允许联合查询、脚本、批处理与一次正确求解；实际轮次不足时调整业务依赖后重测，不强制第21次调用、先犯错或分批揭示静态材料。未实测只报告设计深度及其依据，不声称实际轮次已提升。

## 轮次设计表

作者内部按真实业务填表，不把它变成要求模型照做的步骤清单：

| 环节 | 必要输入 | 实质判断/动作 | 改变的下游结果 | 是否可合理批处理 | 验证证据 |
|---|---|---|---|---|---|
| 从当前材料填写 | 原始位置 | 真实工作 | 业务依赖 | 允许且应计入预估 | 实际产物/日志 |

保守评估能够合并的读取、向量化计算和一次生成多个文件的路径。文件数、行数、情景数与执行步数没有固定换算。规划估计只能叫估计，必须由完整独立作答检验。

可采用的工作来源：

- 异构原始数据需要建立实体与事件连接，多个规则使逐对象结论不同。
- 上游判断改变后续方案；实质情景变化后需要重算，而非同比缩放。
- 面向不同使用者交付不同内容，事实必须一致，内部/外部披露范围明确。
- 在基础环境支持的前提下运行必要计算、测试或求解，并回看结果。
- 用独立样本、替代计算或源数据对账核验关键结果，发现偏差时回源修复。

不采用：规定最低消息数、故意每行一调用、重复开文件、强制进度播报、强制派子代理、无意义转换、要求不用脚本、等待计时、无界调研。也不扩大枚举空间或选择慢算法只为跨过时长线。

## 多轮任务的状态来源与不可逆边界

先确定后轮状态如何产生，两种方式都可使用，但不能混写：

- **固定现场交班：**后轮从预先确定并提供的实际记录起算，不声称现场执行了作答者前轮建议。前轮方案和承诺用于差异比较，实际状态仍由现场记录决定。
- **方案驱动交班：**后轮依据作答者前轮选择与模型可知的业务规则生成，状态变化必须能追溯到实际选择、外部事件与生成规则，不能任意覆盖成作者预设路线。

每轮分开记录已发生事实、当前实物与资源状态、尚可修改的决定。已经历的处理、已形成对象、已消耗或占用的资源，以及已生效的交付不能通过重排计划抹掉；允许的返工或撤销也须有业务依据，并计入资源和时间代价。对象拆并和状态转移保留可恢复的对应关系，避免重复投放、重复售出或把在途资源算成已可用。

若目标是增加多轮决策难度，后轮应保留受当前状态约束的实质待决事项，分别核验存在符合目标的续接或有依据的受限结论；不保证任意错误选择之后仍能全部兑现。只核账、换标题或重复上轮方案，不应声称新增了组合求解难度；业务确实只需要结算时，也不强加生产或重排环节。逐轮判断只能使用当时可见的信息，不要求提前猜中后轮新事实。

## 考点测量

编写、去重、容差、合理替代解与隐性专业判断的边界，集中使用 [考点写法与区分度](rubric-writing.md)。按 [H1–H6 能力层次](task-portfolio.md) 检查哪些真实难点被测到；不能只看格式和概念出现。

考点正文写具体结果和通过条件，依据、解题过程、常见错误及评分取证留作者侧。逐条件核查实际产物，不把“已满足”的自述当作满足；先用正确解、合法替代解和含实质错误的答案校验判定，再解释模型得分。没有识别错误的核验，不能靠高分反推题目容易。

先独立核验标答，再冻结考点、分母与输入版本。若发现考点遗漏真实错误，可以修订为新版本，并对旧产物做单独标记的回溯评分；不得把回溯结果说成新版本的独立试测。原始评分和新评分都保留。同领域有多道题时，分别核验，不把第一题的结果推给整组。

## 可选试测流程

按本次任务范围使用可用模型做诊断；没有试测就只报告改造依据，不承诺实际分数或轮次。

1. 静态检查输入闭合、真实来源、环境和标答；先排除工具不可用造成的低分。
2. 若能节省无效材料制作，先用较小但完整的关键业务范围验证难点，保留该范围内普通记录、历史上下文与自然噪声。小规模不等于只给几行考点材料；作者核算机制用的缩略算例不能直接当模型输入附件。诊断样本只支持局部结论，不能算整题合格。
3. 完整试测前冻结输入和评分版本，记录哈希、模型、配置、运行标识。
4. 新会话只开放 prompt 与输入附件。不要让作答模型接触标答、考点、作者解题表、之前回答或评审意见；文件路径隔离也要落实。
5. 保存原始事件、实际输出与失败。逐模型独立评分，结果不平均、不互相借证据，除非项目明确定义聚合规则。
6. 分别报告错误、得分、有效轮次和时长，比较改造前后的表现，说明还有哪些问题。

自评可作低成本诊断。模型说“我做对了”不构成核验；检查关键数字、原始证据及实际产物，再判断究竟增加了哪些难点。

## 按失败类型修复

| 观察 | 首先核对 | 合理行动 |
|---|---|---|
| 分数高、轮次足 | 路径泄漏、判断太直接、上下游实际独立 | 在原场景中恢复真实证据判断，先验证关键机制 |
| 分数低、轮次短 | 任务是否只需很短的推断 | 加入同一目标下必要依赖、逐对象处理和不同用途的交付 |
| 两项都不足 | 目标是否只需一次汇总，资料是否被作者过度清洗 | 回到真实任务与原始材料，不先扩文件数 |
| 低分来自读不出或无法运行 | 环境限制、缺失数据、损坏文件 | 修复可作答性，排除这类失败对难度的贡献 |
| 轮次多来自等待/错误重试 | 原始事件与有效计数定义 | 分开记录并按规则排除，不计作任务复杂度 |
| 模型答错但仍得高分 | 考点漏测、判定模糊、标答错误 | 修考点/标答，保留版本与回溯评分边界 |

持续围绕观察到的失败修复，不因暂时未达目标就无限扩充附件。保留各版本与试测证据，让下一次改动有明确依据。
