# 原生错误与可恢复噪声

用于附件过于整洁、读入后即可汇总的题目。用户允许主动编写、扩充原生形态的材料，增加错别字、错误数据、错误单位和不统一格式。目标是让模型从相互参照的资料中提炼正确结果，不能只给一套已清洗的标准数据再加背景文字。

## 错误可以设计，恢复依据必须在输入里

区分三个层面：作者用于核验的底层业务事实、模型收到的各来源记录、模型最终应恢复的结果。来源记录允许写错、漏记、重复、过时和互相矛盾；底层对象、事件、数量关系与规则应可解释，最终结果有输入证据支持。作者内部的正确值只能用于验算，不能成为模型唯一缺失的依据。

原件存在时保存原件，在工作副本中改造。扩充材料时，先确定对象、事件、状态和业务范围，再让不同记录环节产生有因由的偏差，例如手工抄录、系统迁移、重复导出、延迟更新或旧模板沿用。可使用脚本批量生成、扰动和验证，不要求逐条手写；随机过程用固定种子或保存完整结果，便于复核版本。

**不能把可恢复理解为附一份干净对照表。** 判断依据应分布在正常业务资料中，如计量记录、出入库明细、包装规格、对象沿革、时间线或生效条款。哪些来源适用于当前对象和时点，也需要判断；复制同一个错误的多个表不是独立佐证。

## 可组合的错误类型

| 类型 | 可主动加入的原生形态 | 输入中的恢复依据与新增判断 |
|---|---|---|
| 错别字、简称与编码差异 | 同音误字、漏字、旧称、前后空格、全半角、编码丢前导零 | 用批次、位置、时间、规格等交叉识别；不能仅按名称相近合并两个对象 |
| 数值录入错误 | 小数点移位、相邻数字颠倒、符号漏写、沿用上一条数量 | 用对应业务记录、数量关系或同对象的独立记录恢复；异常值只能提示核查，不能直接决定改成什么 |
| 错误单位与量纲混杂 | 行内单位错填、表头沿用旧单位、kg/g 混写、箱与件混用、比例与百分数混写 | 结合包装规格、计量定义、批次记录与数量关系判定；不同来源或期间可有不同原因，不做整列盲目乘除 |
| 重复、冲回与多版本 | 重复导出、改版记录并存、原单和冲回单同时出现 | 还原事件而非按整行去重；分清重复记录、合法分批、冲回和重新入账 |
| 漏项与不同含义的空值 | 空白、横线、0、未录、暂估混用；一处缺字段另一处有记录 | 根据业务状态与交叉记录决定补全、保留空值或待核查，不能统一填 0 |
| 日期、文本和数值混排 | 日期格式混杂、数值带单位、千位分隔符、文本数字、跨日补录 | 恢复字段语义、地区格式或时点范围；不能把记录时间当事件时间，也不能破坏代码前导零 |
| 错汇总与旧公式 | 合计漏掉追加行、公式范围过时、粘贴旧结果、汇总和明细不一致 | 按应覆盖对象与期间复算，并判断差异来自记录错误还是合法口径差异 |
| 段落与表格冲突 | 摘要仍用旧结论、表头版本未更新、备注修正未传到主表 | 综合适用范围、效力与事件顺序判断；不能默认表格、正文或最新日期总是正确 |

不必每题用齐。无关痛痒的错别字可以自然存在，但不能把每个错字都当作提难度的核心；优先让一部分错误影响对象归并、数量、资格、金额、容量或交期。保留正常项及看似异常但确实正确的项，避免“看起来怪的一律删掉”也能得分。

## CSV 与表格：增加数据，也保留未经整理的形态

可以扩充对象、记录周期、普通交易、历史状态及不同录入来源，提高批量处理覆盖。扩充时保持对象和事件关系可追踪，而不是只复制同一条记录或随机改几列。

- 不同来源可以使用不同列名、列顺序、日期格式、单位写法和缺失值表示；同一来源中的局部不一致可以来自换版、手录或合并导出。不要把全包预先统一成同一个 schema。
- 在工作簿中保留符合场景的说明行、重复表头、跨行备注、合并标题、多个期间工作表和旧汇总。让模型识别哪些区域是数据、哪些是说明，但不能靠打不开文件制造工作量。
- CSV 可有带单位的文本数字、带换行的备注及空字段；逗号、引号、换行按相应 CSV 规则序列化。内容不规范与文件格式损坏是两件事，反复解析报错不算必要业务轮次。
- 错误可以集中于某个录入渠道、模板或期间，也可以零散出现；不要设计成每隔固定行数必错、某个颜色必错、文件名标出错项。不同来源不必同样干净，也不必按固定比例出错。
- 原生重复导出是需要判定的噪声，可以存在；单纯复制上千行而不增加事件区分、处理覆盖或规则差异，只是在填充。

允许错误多、数据多，不设统一行数或错误比例。增加到什么程度，由恢复依据是否充足、误判是否影响结果及实际处理需求决定；不能把工具能高效处理的记录数换算成必然增加的轮次。

## PDF：可读，不等于清洗或精修

用 TeX 形成可读文档时，可以保留各来源不同的字号、标题习惯、缩写、段落密度、表格样式和局部格式不一致。正文、表头、单位和合计里的设计错误可以保留，让其他材料提供裁定依据。验收时应确认错误按设计呈现，而不是自动把所有数值和单位改成一致。

没有必要把每份文件都排成统一封面、漂亮目录和规范三线表。浅水印、轻微纹理与错别字不能替代有后果的数据错误，也不能掩盖唯一校验依据。具体编译与识读检查见 [PDF 制作](pdf-authoring.md)。

## 把纠错接到必要执行

作者检查这样的依赖是否成立：

`发现不一致 → 关联对象和独立证据 → 判定误录/口径差异/合法异常 → 修复或保留待核查 → 重算 → 更新安排 → 复核`

这不是交给作答模型的操作清单。Prompt 写业务目标与需要交付的可靠结果，不提前说哪些文件有错、哪列单位错误、共几条错误或应按什么倍数修正。

只删空格、统一日期通常能一次批量完成。更有价值的设计是：身份归并改变哪些记录能相加；单位恢复改变可用量；可用量又影响多个对象的资源竞争；发现旧合计漏项后需重算并修改承诺。允许批处理和并行，增加的是不同错误的裁定与上下游影响，而非强制逐行调用工具。

## 作者核验

每类会影响结论的错误，在 [作者记录](../assets/design-record.md) 中写清：位置、错误形态、输入中的恢复证据、适用条件、正确结果或可接受范围，以及受影响的后续计算与安排。只有装饰作用的错字不必逐个建考点。

交付前核对：

1. **可恢复。** 不看作者正确值，仅从模型输入能否复原关键结果？至少有未被同一错误污染的判别依据；“这个数看起来不合理”不足以确定修正值。
2. **不误修。** 检查普通项、合法极值、正常重复事件及合法单位差异；清洗不能删掉正确业务记录。证据确实不足的局部项保留待核查，并传到下游。
3. **会传导。** 分别代入表面错值与恢复值，核对是否影响应交付的数量、资格、金额、容量、顺序或承诺；无影响的变化不虚报为主要难点。
4. **没有答案捷径。** 输入中没有作者添加的正确值列、错误标志、修正映射、固定异常颜色或干净答案页。必要的原始业务记录可以作为证据，但不能由作者把它们整理成万能答案表。
5. **保留预期的脏。** 打开并抽查导出的文件，确认工具没有把错字、混合类型、错误单位、旧汇总顺手修掉；也没有引入设计之外的乱码、丢列、截断或无法恢复的矛盾。

如需对照验证，作者可在相同底层任务上保存一份已修复输入，比较两版的判断、产物与执行记录；这份对照只用于验证，不放入正式模型输入包。尚未跑测时只报告设计依据。

作者的生成过程、错误台账、修复值和核验记录均留在作者侧；附件不添加“模拟数据、构造数据、脱敏数据、仅供测评”等制作说明。这里说明的是出题方法，不应把方法文字或缩略示意直接复制为正式附件。
