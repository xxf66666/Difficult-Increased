# 出题难度与有效轮次设计

把模型当作接手真实工作的同事。目标是让它在可完成的业务任务中自行找证据、形成判断、执行并校验；不能用缺材料、工具障碍、故意模糊交付要求或强制碎步制造失败。

难度由 **prompt 与模型可见的输入材料**承载；考点负责测量表现，标答和作答思路用于验证。修改评分不能把本来完成得很好的任务变难。

**可以有意设计难度。** 主动调整证据分布、对象关联、规则交叠、状态变化和下游依赖，让模型必须完成更多判断与必要工作。设计要遵守业务逻辑、信息闭合和可解性，不必停留在“原件有什么就总结什么”。

## 核心工作法

工作范围只有四项：prompt 改造、输入附件改造、难度与必要执行的联动设计、改造效果验证。先读用户提供的原始材料与现有 prompt，找出这项工作真正要解决的决策。已有题目升级时保留原场景和核心目标。**主要成果应是 prompt 与附件的实质改进，不能用一份门槛表或泛泛建议代替。**

读取 [可复用改造方法](references/transformation-playbook.md)，按以下顺序推进：

1. **定位过度代劳。** 作者是否已经给出了附件用途、有效版本、清洗结果、判断标准或操作顺序？找出这些降低判断成本的位置。
2. **回到原始输入。** 找回真实来源中的背景、历史项、分歧、例外和对象连接，保留足够噪声，让信息筛选与关联成为必要工作。
3. **接通业务依赖。** 一个证据判断应改变后续计算、选择或交付；不同环节服务同一目标。让复杂判断发生在必须完成的工作上。
4. **改 prompt 与附件。** prompt 留清晰的委托和交付边界；附件承载可恢复的事实、规则、分歧与线索。确实需要补充原件时列出具体缺口，不能用假业务记录填空。
5. **逐项解释作用。** 在作者记录中说明改了什么、来自哪里、要求新增哪种判断、带来哪些必要工作、为什么仍然可解。没有实质作用的改动撤回。

方法可跨项目复用；每次要从当前真实材料落地，不套造统一的“高版本制度＋撤销邮件＋供应商榜单”故事。

## 提示词与附件是两个主要工作面

### 提示词：明确委托，把推理留给模型

写清业务目标、使用者、决策时点、交付物和必要验收边界。不要把作者的解题流程、公式推导、异常位置、正确证据或考点清单塞进题面，也不要逐份解释附件用途。可保留中性的文件目录、真实业务术语和必要参数；**从题面移出的必要信息必须仍能从输入或可用公开来源恢复。**

先独立检查：如果只看 prompt 就知道该找哪一行、用哪条特殊规则、怎样得出答案，提示过多；如果具备岗位能力的人仍无法知道要交什么，要求不足。具体改写与附件检查见 [提示词和输入附件](references/prompt-and-attachments.md)。

### 附件：保留原始噪声，让有效信息需要被找出来

**附件硬要求：不得把几行文字、几行数据或一条规则单独包装成一份模型输入附件。** 尤其禁止为一个考点制作一份只含关键线索的小文件，让模型打开就能看出“这份材料就是让我处理这个例外”。发现这种附件应先退回重做，再讨论增加其他难点。

附件必须有足够的业务内容和自然噪声：完整的相关上下文、普通记录、历史项、例行字段、非关键段落以及不同对象或状态的信息。关键证据应处在这些材料中，要求模型先筛选与辨别，再关联判断；不能只有几条答案线索，再象征性加一两句背景。短消息或短条款应保留在对应邮件链、业务记录或制度上下文中，不能拆成单独的考点文件。

优先使用真实原始导出、旧版材料、邮件摘录、日志、批注和交接记录，保留与任务相关的背景与冗余；不要先替模型整理成答案总表。关键证据可以分散，但对象标识、时间、单位、版本、权限和连接依据必须可恢复。矛盾须有业务原因和裁定依据；允许局部保持待核查，不能让整题无法完成。

这里的“噪声多”是实质要求：必须让筛选、排除、核对和关联成为必要工作；不设文件数、页数、噪声比例或脏行数量的通用配额。重复段落、复制记录、随机无关文本、大字号、空白页和水印都不能补足内容。具体反例、改造与逐附件检查见 [提示词和输入附件](references/prompt-and-attachments.md)。本技能中的小数据教学例只用于解释机制，不能直接复制成正式输入附件。

**PDF 约定：**新建、重排 PDF 使用 TeX / LaTeX，保存 `.tex` 源码和编译记录。已有原始 PDF 保留来源，不为统一风格重造。可加入浅水印和少量不遮挡内容的视觉噪声；不靠模糊、破坏文本层或盖住数字降低可读性。详见 [PDF 制作](references/pdf-authoring.md)；水印不能替代业务信息噪声。

## 选择并组合难度机制

按需要读取 [难度机制](references/difficulty-mechanisms.md)，优先组合会互相影响的机制：

- 证据是否有效：权限、生效时间、对象、范围、撤销状态共同决定，不能只取最新日期。
- 真正判断标准：从目标和当前瓶颈推导，不能盲从现成榜单或表面指标。
- 多规则组合：对象状态、适用条件、覆盖关系、例外共同改变结果。
- 局部不能继续：有证据地保留待核查或不可执行状态，并传递到下游产物。
- 口径与粒度：对象、税币、期间、统计层级、容量与状态之间需要还原和转换。
- 决策与复算：便捷方案会违反真实约束；情景变化确实改变可行域和后续交付。

需要更深的改造时，按痛点读取专项方法库，不必一次加载全部：

| 题目目前容易在哪里 | 读取的专项方法 |
|---|---|
| 搜到一个数或一段文字就能下结论 | [跨文件证据](references/cross-file-evidence.md)：实体拆并、双时间、证据依赖、跨模态核对、调节关系 |
| 各规则分别看都能直接套用 | [跨规则组合](references/rule-composition.md)：适用域、顺序、状态触发、共享资源、边界与最小修复 |
| 判断完就结束，各环节可以互不相干地完成 | [难度与执行联动](references/coupled-execution.md)：竞争解释、判别验证、变更传播、反例修复与收敛 |

作者内部为每个难点记下：原始证据位置、正确判断及依据、合理替代解、常见误判、下游影响、对应考点。可用 [设计与审查记录](assets/design-record.md)。这张表不得进入模型输入包。

## 让轮次来自必要工作

画出最小业务依赖链：哪些判断会改变后续输入，哪些结果必须在交付前复核。增加工作前回答：删掉这一环节会损失什么真实业务能力？若只是少读一份重复材料、少写一条进度或少导出一个同内容格式，不应保留为提轮次手段。

有效路径包括异构原始资料整合、不同规则下逐对象判定、约束变化后的重算、面向不同岗位的相互一致产物，以及基础环境支持的真实执行和必要验证。允许高效脚本、批处理与并行，不故意阻断模型正常效率。

具体设计时，把“找到事实”接到“改变对象状态”，再接到“改变规则适用、方案或交付”。例如：跨源还原可用资源 → 判断哪些规则在当前状态成立 → 处理多个对象竞争 → 给出方案 → 用独立证据或情景检验并修正。各环节的困难应落在同一业务结果上，而不是一边单独放难题、一边另加大量简单劳动。

**用户交互轮数、主模型 assistant 消息数、工具调用数、有效执行轮次与运行时间分别记录。** 子代理调用和工具返回不自动并入主模型；等待、报错、重试按项目口径归类，不能偷换成有效推理。附件数与页数不能证明轮次达标。详见 [轮次、评分与试测](references/rounds-and-validation.md)。

## 保证评分公平、答案可核验

每个考点对应一个可观察的能力或结果，给出证据位置、通过条件、误差及典型失败条件。检查真实判断与结果，不能只检查“提到了某概念”。必要交付条件可以严格，不能添加输入无法恢复的隐藏标准。

用当前任务已有的评分方式衡量表现。避免为压分删除必要要求、把一个错误拆成多次重复扣分或限定作者唯一解法。半开放任务接受满足目标与约束的合理替代解。标答独立复核；要求文件产物时，实际检查对应产物，不能只用文字声称已完成。

## 验证后再判断状态

使用用户给定的模型与计数口径，不设统一分数线或轮次线。未知数值不妨碍先改进 prompt 与附件。

先核验可解性、证据闭合与必要工具是否可用，再按本次任务范围做小规模核心试测，确认机制有效后才扩大材料。小规模是缩小业务覆盖范围，仍保留该范围内完整上下文和自然噪声，不能退化成几行考点附件。试测模型只接触固定版本的 prompt 与输入附件，隔离标答、考点、作者笔记及历史回答；保留输入版本、原始轨迹和实际产物。

分别报告判断错误、得分、有效轮次与必要执行的来源；有时长目标时再记录时长。没有对应证据时写“未测”或“证据不足”。自评可以帮助定位问题，不替代对产物和原始记录的独立核验。

分数高而轮次够：修证据推理、决策依赖或提示泄漏，停止堆材料。分数低但无法正常作答：先修材料和环境。只要输入或考点改动，给新版本；不得把旧试测结果追认到新版本。

## 按当前范围交付

只输出用户本次需要的修订题面、附件、改造记录或试测结果。需要隔离时可分 `model-input/`、`author-only/`、`trial-evidence/`，不把内部模板全量塞给用户。

汇报具体改动、对难度与轮次的预期作用、实测证据与仍未解决的问题。未试测的改动只报告设计依据，不承诺一定达到某个分数或轮次。
