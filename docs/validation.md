## 技能结构

- 使用 skill-creator 的 `quick_validate.py` 核对前置信息、命名与描述。
- 检查所有 Markdown 相对链接可解析。
- 检查安装后的 `SKILL.md`、引用文件、作者记录模板和 Codex 元数据完整。
- 检查范围聚焦于 prompt、输入附件、判断难度、必要执行及效果验证。

系统 Python 与现有 Codex Python runtime 均未带 PyYAML，技能校验通过 `uv run --with pyyaml` 使用隔离依赖；安装器本身只依赖标准库。

## 独立使用试验

给独立 Agent 技能目录和一个描述性请求：原题让模型按已整理的供应商交付能力排名写报告，20 行输入已经包含有效产能、有效版本和建议选择；用户另有订单、周排产、延期邮件、未生效变更与交接记录，但未提供原件。要求给出可实施的 prompt 与附件改造，而非调整门槛。

实际输出：[供应商交付安排改造示例](examples/supplier-delivery-redesign.md)。这是技能行为试验，不是已交付的真实题目。

观察到的行为：

- 识别作者提前给出有效容量、版本和选择造成的低判断成本。
- 提供可替换的题面底稿，去掉“先排名再选”的路径，保留交付用途与边界。
- 按订单、排产、变更、交接及历史邮件分别给出具体材料需求与改造作用。
- 将跨源判断接到逐单安排与不同用途产物，没有建议堆 PDF 数量或强制工具次数。
- 区分未看到的原件、方案、未制作附件和未实测指标，没有捏造改造效果。

限制：本次未提供真实原件，也未进行改造前后目标模型的对比跑测。因此只能支持“技能能引导具体改题方案”，不能支持“已验证降低得分或增加有效轮次”。PDF 指导已编写，本次未生成或验收具体业务 PDF。
